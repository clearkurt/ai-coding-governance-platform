# 企业内部 AI 编程助手：LLM Agent 重构需求

## 目标

平台升级为“服务端 LLM Agent + 本地受控工具”的架构。LLM 运行在服务端或公司内网模型网关，不部署在 Windows Agent 中；源码访问和文件修改仍由本地 Agent 执行。

## 核心流程

1. 用户在网页输入需求并选择会话。
2. API 创建一次 Agent run，注入公司代码规范、用户上传源码和会话上下文。
3. 服务端 LLM 通过本地 Agent 工具直接访问授权工程目录、读取文件并生成修改。
4. API 将 LLM 的工具调用转换为 Agent 任务；Agent 执行后把真实文件结果返回给 LLM。
5. LLM 可以生成 `stage_patch`，也可以在用户授权的写入模式下发起 `apply_patch`。
6. 网页展示执行计划和 diff；用户确认后允许写入，或由企业策略配置为自动应用。
7. Agent 重新校验原文件 SHA-256 后写入；API 记录完整操作链。

## 安全约束

- LLM 可以通过 Agent 工具直接读取和写入本地工程，但不能执行 Shell、编译器或任意进程。
- Agent 是本地路径和写入权限的最终边界；服务端不接收绝对路径。
- 所有写入必须经过企业策略允许、原文件哈希校验和审计；默认仍要求用户确认。
- 模型请求使用公司内网或受控模型网关；生产环境禁止使用开发默认密钥。
- 模型输出必须经过结构化 schema 校验，不能把自然语言直接当作工具参数执行。

## 当前阶段交付

- API 模型 provider 可配置为 OpenAI-compatible HTTP 接口。
- `NODE_ENV=test` 或显式开发开关继续使用 Mock provider，保证离线测试可运行。
- Agent 工具协议逐步扩展为 LLM tool-call 的中间层；先接通读取上下文，再接通 patch 预览和确认。
